## Cuándo usarlo

- Para una tarea corta que se resuelve sin salir de la pantalla: programar, confirmar una baja,
  cambiar un dato puntual.
- Para confirmar una acción destructiva lanzada desde un [menú de acciones](/componentes/menu-acciones/).
- Para un formulario largo o con varios pasos, usa una pantalla completa de
  [formulario](/componentes/formulario/).
- Para informar sin pedir nada, usa un [aviso](/componentes/aviso/). Un diálogo interrumpe.

1. **Velo** — `::backdrop` en `--velo-modal`. Detrás se ve la pantalla real atenuada.
2. **Contenedor** — `dialog.modal`: hasta 520px de ancho, `--surface`, radio `--r-modal`, sombra
   `--sh-modal`. Columna flexible.
3. **Cabecera** — título `h2` a `--fs-sub` y botón de cerrar, con borde inferior.
4. **Cuerpo** — `.cuerpo`; desplaza por dentro si el contenido no cabe.
5. **Pie** — acciones alineadas a la derecha, la primaria al final, con borde superior.

## Comportamiento

### Centrado y tamaño

`margin: auto` es el centrado nativo del diálogo. **No le declares un margen propio**: lo anula y
el diálogo se pega a la esquina superior izquierda.

```css
dialog.modal {
	border: 0;
	padding: 0;
	margin: auto; /* centrado nativo: no lo sobrescribas */
	max-width: 520px;
	width: calc(100% - 32px);
	max-height: calc(100dvh - 64px);
}
dialog.modal[open] { display: flex; flex-direction: column; }
dialog.modal::backdrop { background: var(--velo-modal); }
dialog.modal .cuerpo { overflow-y: auto; }
```

El alto máximo deja 32px de aire arriba y abajo. Cabecera y pie quedan fijos; solo el cuerpo
desplaza.

### Foco

1. Al abrir, el foco va al **primer control que se puede rellenar**, no al diálogo ni al botón de
   cerrar. Márcalo con `autofocus`.
2. Mientras está abierto, `Tab` cicla dentro. Lo da `showModal()`.
3. Al cerrar sin guardar, el foco vuelve **al control que lo abrió**.
4. Al cerrar guardando, el foco va **a la fila o el elemento que cambió**; si ya no existe, al
   contenedor más cercano. Nunca al `body`. Una `<tr>` necesita `tabindex="-1"` para recibirlo.

### Cierre

- `Escape`, el botón de cerrar y «Cancelar» cierran sin guardar.
- **Mientras una operación está en curso, nada cierra el diálogo**: ni `Escape`, ni el botón de
  cerrar, ni el clic en el velo. Cerrar a medio guardar deja a la persona sin saber si se guardó.

```js
dlg.addEventListener('cancel', (e) => {
	// Escape
	if (dlg.dataset.momento === 'guardando') e.preventDefault();
});
```

### Contenido

- **El nombre del botón y el contenido coinciden.** Si «Editar cliente» solo deja cambiar la razón
  social, se llama «Cambiar razón social».
- **Un campo de solo lectura se muestra como dato**, no como campo desactivado, con el motivo al
  lado. Un campo gris sin explicación se lee como un fallo del formulario.
- **Detrás va la pantalla real atenuada**, no un esqueleto de carga: las barras grises se leen como
  «cargando» y hacen pensar que se perdió el sitio en la lista.

## Accesibilidad

- Usa `<dialog>` y ábrelo con `showModal()`. Un `<div role="dialog" aria-modal="true">` obliga a
  reimplementar velo, capa superior y trampa de foco.
- Nombra el diálogo con `aria-labelledby` apuntando al título.
- El botón de cerrar es un [botón-icono](/componentes/boton-icono/) con `aria-label`.
- `Escape` cierra salvo durante una operación en curso.
- El foco entra al primer campo y vuelve al disparador o al elemento modificado.
