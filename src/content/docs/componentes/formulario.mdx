## Cuándo usarlo

- Para dar de alta o editar un registro: cliente, sucursal, orden.
- Para adjuntar un documento, usa la [subida de archivo](/componentes/subida-archivo/) dentro del
  formulario, nunca un campo de texto.
- Para confirmar una sola decisión, usa un [diálogo](/componentes/dialogo/).

## Anatomía

<Example noCode>
	<div class="ctrl" style="max-width:320px">
		<label for="fm-an">Teléfono <span class="opc">(opcional)</span></label>
		<input type="tel" id="fm-an" aria-describedby="fm-an-a" />
		<span class="ayuda" id="fm-an-a">Diez dígitos, sin espacios.</span>
	</div>
</Example>

1. **Sección** — una [tarjeta](/componentes/tarjeta/) con cabecera; la cabecera dice qué falta, en
   palabras.
2. **Rejilla** (`.rejilla`) — columnas `auto-fit` de 230px como mínimo; `.ctrl.ancho` ocupa la fila
   entera.
3. **Rótulo** (`<label>`) — `--fs-meta`, peso 600, en `--text-2`. Lo opcional lleva «(opcional)»
   en `.opc`.
4. **Control** — alto mínimo 38px, borde `--border-ctrl`, fondo `--bg`.
5. **Ayuda** (`.ayuda`) — `--fs-meta` en `--text-2`, enlazada con `aria-describedby`.
6. **Error** (`.mal`) — ícono y texto en `--err-ink`, peso 600; sustituye o acompaña a la ayuda.

## Variantes

| Variante | Clase | Úsala para |
|---|---|---|
| Campo | `.ctrl` | Un dato que escribe quien llena el formulario. |
| Campo ancho | `.ctrl.ancho` | Domicilios, notas: textos que no caben en una columna. |
| Dato calculado | `.dato-calc` | Un valor que el sistema deduce. Se muestra como dato, no como campo. |

**Un dato calculado no es un campo.** Un campo editable con el texto «Se calcula solo» se puede
borrar y enviar como dato. Muestra rótulo y valor real («Empresa») y una nota corta de dónde se
deduce.

| Estado | Comportamiento |
|---|---|
| Reposo | Borde `--border-ctrl`. |
| Foco | Anillo `--focus-w` en `--accent`. |
| Error | `data-error="true"`: borde y halo de 1px en `--err`; mensaje `.mal` debajo. |
| No disponible | Botón con `aria-disabled="true"` y el motivo junto a él, enlazado con `aria-describedby`. |

- **No hay error antes de la interacción.** El error aparece cuando la persona ya pasó por el
  campo, no al cargar el formulario vacío.
- **El error dice qué falta y por qué importa**: «Falta el domicilio fiscal. Sin él no se puede
  timbrar una factura a este cliente».
- **Un botón deshabilitado no recibe foco**, y quien navega con teclado nunca llega a la explicación.
  Usa `aria-disabled="true"` y explica el motivo al pulsarlo.
- **Si el motivo dice «quita uno», la forma de quitarlo existe.** Si no se quiere borrar, ofrece
  «Archivar» o «Marcar como no vigente».

## Uso

**Dos niveles de obligatoriedad, con palabras distintas.** «Obligatorio para dar de alta» (sin esto
no hay registro) lleva `required`. «Necesario para facturar» (el registro existe pero no opera) lo
dice en la ayuda. Lo demás se marca «(opcional)».

## Accesibilidad

- Cada control tiene `<label for>`. El rótulo visible es el nombre accesible.
- Lo obligatorio lleva `required` y `aria-required="true"`. Si usas asterisco, va con
  `aria-hidden="true"` y una leyenda al inicio del formulario.
- El error se enlaza, no se coloca al lado: `aria-invalid="true"` en el control y
  `aria-describedby` con el `id` del mensaje. La ayuda se enlaza igual.
- El tipo del campo es el tipo del dato: `type="email"`, `type="tel"`, `inputmode="numeric"` en el
  código postal, y `autocomplete` donde corresponda. En teléfono sale el teclado correcto.
- En pantallas táctiles el texto de los controles sube a 16px como mínimo: por debajo, el navegador
  amplía la página al enfocar.
- Cada `id` es único en la página. Dos mensajes con el mismo `id` hacen que `aria-describedby`
  resuelva siempre al primero.
